# Deforestation Detection from Satellite Images

Map forest cover from free Sentinel-2 imagery with a U-Net, compare two dates,
and flag newly cleared areas on an interactive map.

| | |
|---|---|
| **Stack** | Python · Google Earth Engine · rasterio + NumPy · PyTorch + segmentation-models-pytorch · folium |
| **Data** | Sentinel-2 L2A (10 m, free) + Google Dynamic World "trees" labels |
| **Hardware** | GPU for training (free Colab/Kaggle); free Earth Engine account (noncommercial) |
| **Metrics** | IoU and F1 for the forest class on held-out **areas**, vs an NDVI baseline; hectares cleared |

## Study area & dates
- **Region:** Colniza, Mato Grosso — Brazilian "arc of deforestation" (a documented clearing hotspot). Config in `src/data/regions.py`.
- **Dates:** two dry-season windows in different years — `2020-07-01..2020-08-31` and `2022-07-01..2022-08-31` (same season, so seasonal green-up is not mistaken for clearing).

## Setup
1. `python -m venv .venv` then activate (`.venv\Scripts\activate` on Windows).
2. `pip install -r requirements.txt` (pinned).
3. Authenticate Earth Engine and set your Cloud project:
   ```powershell
   earthengine authenticate
   $env:EE_PROJECT = "your-cloud-project-id"
   ```
4. On Windows, if `rasterio` raises a PROJ error, `PROJ_LIB` is being shadowed by
   another GDAL/PROJ install. The VS Code terminal and launch configs already
   override it; for a plain shell:
   ```powershell
   $env:PROJ_LIB = ".venv\Lib\site-packages\rasterio\proj_data"
   ```
5. Run training on Colab/Kaggle (free GPU) — the scripts are identical locally and
   there; `notebooks/04_train_colab.ipynb` is a ready-made wrapper. No Earth Engine
   yet? `python src/data/make_synthetic.py` writes dummy GeoTIFFs so you can smoke-test
   the whole tile → train → evaluate path offline.

## Pipeline (steps → scripts)
| Step | Command |
|---|---|
| 1 Region + dates | `src/data/regions.py` |
| 2 Pull & clean imagery | `python src/data/pull_imagery.py --export-labels` |
| 3 Dynamic World labels | `src/data/labels.py` |
| 4 NDVI baseline | `python src/baseline/build_baseline.py --export-labels` |
| 5 Tile + split by area | `python src/data/prepare_tiles.py --image data/raw/t1.tif --label data/raw/dw_trees.tif` |
| 6 Train U-Net | `python src/train.py --data-dir data/tiles --epochs 30` |
| 7 Evaluate + inspect failures | `python src/evaluate.py --data-dir data/tiles --split test` |
| 8 Change detection + map | `python src/pipeline.py --t1 data/raw/t1.tif --t2 data/raw/t2.tif --meta data/tiles/meta.json --unet --checkpoint results/unet.pth --save-mask data/processed/cleared.npy --map results/clearing_map.html --metrics results/metrics.csv` |
| 9 Standalone map | `python app/map.py --t1 data/raw/t1.tif --t2 data/raw/t2.tif --cleared data/processed/cleared.npy` |

Change detection (step 8): forest mask for each date → `cleared = before & ~after`
→ connected-component filter dropping patches `< --min-pixels` (**50 px ≈ 0.5 ha**
at 10 m) → total hectares printed and burned into the map legend. Hectares use the
pixel's true ground area (0.009846 ha/px here), computed from the raster's
resolution and latitude; override with `--pixel-area-ha` if needed. The map stacks
the date-1 and date-2 RGB layers (toggle in the layer control) with the cleared
areas in **red**.

### Inspecting failures (step 7)
`evaluate.py` reports IoU/F1 vs the NDVI baseline and writes two diagnostics:
- `results/worst_tiles.png` — a contact sheet of the lowest-IoU tiles showing the
  input band, label, prediction, and an error map (**red** = false positive,
  **blue** = false negative). On this run the worst tiles are all
  low-forest-cover mosaic / degraded-regrowth scenes (9.7–22.1% forest, no water)
  where the model misses canopy that sits just under the NDVI 0.6 threshold — the
  errors are false-negative heavy, not water or shadow artifacts.
- `results/per_tile.csv` — per-tile IoU/F1 and tp/fp/fn counts for sorting.

Tune with `--snapshot`, `--per-tile-csv`, `--worst-k`, `--threshold`, and pass a
precomputed `--baseline-iou` to skip the NDVI pass.

## Design decisions & common mistakes
- **Split by area, not randomly.** Neighbouring tiles are near-identical, so a
  random split inflates scores. `src/data/split.py` holds out whole geographic blocks.
- **Same season, different years** for the two dates — never compare across seasons.
- **Mask clouds/shadows** via the SCL band (`src/data/earth_engine.py`) or they get
  flagged as cleared forest.
- **Dynamic World labels are model predictions**, not perfect ground truth —
  spot-check them by eye before trusting them.
- **Metric:** pixel accuracy misleads (forest dominates); report IoU/F1 for the
  forest class.
